## Супервизор соединения

`tcbot/runner.py` держит SDK-бота под наблюдением. Зачем это нужно:

библиотека `python-trueconf-bot` умеет переподключаться, но её цикл
соединения завершается окончательно в ряде ситуаций (исчерпаны попытки,
сервер отверг токен, сессия зависла без обрыва TCP). После этого объект `Bot`
уже не восстановит WebSocket, а приложение продолжит работать «вхолостую».

### Что делает супервизор

1. Запускает `bot.run()` и ждёт готовности.
2. Следит за `connected_event` / `authorized_event`.
3. Периодически проверяет связь активным запросом (`heartbeat`).
4. При сбое — пересоздаёт `Bot` целиком и пробует снова.

### Режимы heartbeat

| Режим | Поведение |
|---|---|
| `off` | реагируем только на события SDK |
| `smart` | активная проверка; перезапуск после 3 неудач подряд |
| `strict` | перезапуск сразу после первой неудачной проверки |

Если сервер отвечает **ошибкой API** (а не сетевым сбоем), проверка
автоматически отключается — иначе получались бы ложные перезапуски.

### Пауза между попытками

```
простой < RECONNECT_FAST_WINDOW (10 мин):
    5с → 10с → 20с → 40с → 80с → 160с → 320с
простой ≥ RECONNECT_FAST_WINDOW:
    1800с → 1800с …   (одна попытка в 30 минут)
```

Первые 10 минут бот подхватывает короткие обрывы почти сразу. Дальше — это уже
плановые работы: темп падает до одной попытки в полчаса. После восстановления
связи пауза сбрасывается.

Через `QUIET_AFTER` (10 минут) включается «тихий» режим: в `error.log`
остаётся только первая ошибка, остальное — в `bot.log` и в панели.

## Очередь недоставленных

Системы мониторинга повторяют вебхук несколько раз за десятки секунд и
сдаются. При часовых работах на TrueConf уведомления были бы потеряны —
поэтому `tcbot/outbox.py` сохраняет их на диск.

```
недоставка → POST /webhook → 202 + запись в bot_outbox.json
связь есть  → фоновый flusher отправляет накопленное по порядку
```

| Свойство | Как реализовано |
|---|---|
| Переживает перезапуск | JSON-файл, атомарная запись (tmp + replace) |
| Порядок | FIFO |
| Дубликаты | окно дедупликации `OUTBOX_DEDUP_WINDOW` |
| Схлопывание | по одному триггеру остаётся последнее состояние |
| Ограничения | `OUTBOX_MAX_SIZE` сообщений, `OUTBOX_TTL_HOURS` часов |

При переполнении вытесняется старейшее сообщение; счётчик потерь виден
в панели.

## Разметка сообщений

TrueConf Server разбирает разметку не так, как ожидается. Проверено на 5.5.8:

| Что делаем | Что было бы иначе |
|---|---|
| не используем обратные кавычки | MARKDOWN превращает их в `<code lang="pre">`, клиент этот тег не понимает |
| экранируем `<` и `>` | сырое `<id>` сервер считает тегом и выбрасывает |
| маркер списка `•` вместо `-` | строка с дефиса в MARKDOWN склеивается с соседней |
| перенос строки — `<br>` | сырой перевод строки в HTML не даёт переноса |
| структурированные сообщения — `ParseMode.HTML` | MARKDOWN теряет часть форматирования |

Всё это инкапсулировано в `tcbot/markup.py`: `MessageBuilder` экранирует любое
внешнее значение и отдаёт готовый HTML. Текст уведомлений проходит через
`safe_text()`.

Дополнительно `normalize_command_text()` очищает входящие команды от невидимых
символов: клиенты могут прислать `/channels&nbsp;2` или вставить zero-width
пробел, из-за чего команда перестаёт распознаваться.

## Логирование

| Файл | Содержимое |
|---|---|
| `bot.log` | всё, уровень DEBUG |
| `chat.log` | входящие сообщения и команды |
| `webhook.log` | приём вебхуков |
| `error.log` | ошибки отправки и сбои связи |
| `delete.log` | удаление сообщений |
| `error_history.log` | история инцидентов |

Ротация: 50 МБ × 10 файлов. Собственные обработчики библиотеки `trueconf`
отключаются при старте, поэтому каждое событие попадает в лог одной строкой.

## Структура проекта

```
bot_multy.py          точка входа: команды, вебхуки, API, сборка приложения
config.py             конфигурация из окружения
check_stack.py        проверка окружения перед запуском

tcbot/
  runner.py           супервизор соединения (переподключение, heartbeat)
  outbox.py           durable-очередь недоставленных
  markup.py           сборка HTML-сообщений для TrueConf
  state.py            состояние, администраторы, токен
  logging_setup.py    общий лог и раздельные каналы
  frontend.py         разметка главной страницы панели
  pages.py            страницы разделов
  theme.py            дизайн-система (CSS)
  appjs.py            клиентский скрипт панели
  auth.py             авторизация панели
  sso.py              OIDC-клиент Keycloak
  localadmin.py       локальная учётная запись (PBKDF2)
  sdkinfo.py          данные из SDK для страницы диагностики
  metrics.py          история метрик для графиков и календаря

scripts/              офлайн-тесты
docs/                 документация
```
